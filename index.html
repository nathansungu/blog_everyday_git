Git

what's Git ?

It is is a distributed version control system (DVCS) that tracks changes in files and directories, allowing developers to collaborate on projects and maintain a history of modifications

Whats version control

version control is a system that tracks and manages changes to files and directories over time, allowing developers to easily revert to previous versions, collaborate effectively, and understand the history of a project.

Git as version control

Git, as a version control system, is a distributed system, meaning each developer has their own complete copy of the project's history, facilitating independent work and collaboration.

Other version Controls

  1. Mercurial Developers and businesses adore Mercurial for its search capabilities, backup system, data import and expor
  2. Apache Subversion is a version control system distributed as open source under the Apache Licens
  3. AWS CodeCommit is a secure, scalable, fully managed version control tool that hosts private git repositories, similar to that of GitHub and GitLab
  4. Bitbucket. As a component of the Atlassian software family, Bitbucket can be connected with other Atlassian products like HipChat, Jira, and Bamboo.

Adding files to the staging area

What is the Staging Area in Git?

The staging area (also called the index) is a place where Git gathers changes before committing them to the repository. It acts like a preview zone for your next commit—you select exactly which changes should be included. Only the files in the staging area will be committed when you run git commit.

Diffrence between tracked and untracked files

  • TrackedFiles that Git is already aware of. They were in a previous commit.
  • UntrackedFiles that are in your project folder but have never been added to Git.

Steps to stage files

  • on terminal git add. To add all files.
  • git add FILE_NAMe to add aspecific file.

Commit changes

Files that are in your project folder but have never been added to Git. Commit message should explain why the commit is made. Example, "correct spelling error on index file"

Add commit

To commit, changes must be first be staged by use of git add .

Check if changes ARE STAGED

    • Staged files will be displayed else stage the files

Steps to commit

  • git commit -m "commit message". This will commit the changes with message tag.

Writing Good commit message

A good commit message should answer the question What will the commit do?. For example a change on spelling eror on the previous commit, the commit message should be correct spelling error

Go back to particular commit

Git alows one to roll back to a particular commit in case of the new version being unstable or contant crashing. To roll back to a commit follow the steps below

Steps to roll backup

  • Start by displaying all the commits by git log --oneline
  • On the logs displayed copy the commit hash
  • On terminal enter git revert
  • This will roll you back to your desired commit

Merging a branch

Merging a branch in Git means combining the changes from one branch into another. Typically, this happens when you want to bring the changes you've made in a feature branch (or any other branch) into your main branch .

Steps to merge

  • Make sure you're on the branch you want to merge into
  • Use the git merge command to merge another branch (like a feature branch) into the current branch.
  • git merge branchtomergefrom

Deleting a branch

You can delete a local branch that you've finished with by

  • In the brach you want to delete, enter
  • git branch -d branch-name

To forcefuly delete a brach

Use a capital flag -D to forcefully delete a brach that is yet to be fully merged.

  • git branch -D branch-name
